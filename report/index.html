02 · NETWORK MODEL

Where does a 99-player game create pressure?

Use a server-authoritative star architecture. Clients upload inputs, the server validates them and advances the canonical world, then distributes compact state changes.

01 Client input direction · action · sequence
10–20 Hz
02 Authoritative server validate · simulate · resolve
delta state
03 Client rendering interpolate · predict · 60 FPS
A

Send inputs, not truth

Never trust client positions directly. Process sequenced inputs and enforce movement limits on the server to reduce cheating and divergence.

B

Update slowly, render smoothly

Start the server at 10–20 Hz while clients render at 60 FPS. A 100–150 ms interpolation buffer can smooth remote movement.

C

Synchronize only what matters

Use delta state, quantized coordinates and interest management instead of broadcasting the complete world every frame.

03 · TECHNOLOGY DECISION

Multiplayer technology decision

The goal is not the platform with the most features. It is the shortest path to a measurable 99-player prototype.

RECOMMENDED

Colyseus + Node.js / TypeScript

The strongest match for the existing Phaser and TypeScript stack. Rooms, lifecycle hooks, matchmaking and schema-based delta synchronization are available out of the box, so the team can focus on game rules and player experience.

  • Server-only authoritative state mutation
  • Binary property-level delta patches
  • Room capacity, reconnection and matchmaking
  • Shared TypeScript types across the stack

The next phase requires a real server and staged headless-client load tests that record tick duration, CPU, memory, bandwidth and latency.
